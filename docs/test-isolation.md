# 测试隔离与证据方案

状态：P0 方案，运行验证按各实现阶段执行。适用全部 Agent、CI 及独立复核。

## 执行边界

本地不得构建、测试、启动服务、执行验证脚本或容器。只在公开 newapi-rs 的标准 GitHub-hosted Linux runner 执行；禁止 self-hosted/larger runner、生产凭证及收费外部调用。Go 参考固定为 `17970da4571e81308f176a0e61a38276e5771606`，只读 checkout，测试在 runner 临时副本执行，不推送上游。

## 数据库

P1 使用每 job 独立 SQLite 临时文件和 PostgreSQL service 容器；测试用户名、密码及库名仅为一次性 fixture，不复用任何生产账户。服务端口只用于该 runner/job，连接信息不接受仓库 secrets 或开发机环境继承。并行矩阵不共享数据库，测试间按独立数据库/schema/临时文件隔离，finally 清理；job 结束由 hosted runner 销毁。

用户已明确不支持 MySQL，不设置其实现或验收矩阵。PostgreSQL 最低支持版本已由用户修订为 14（2026-11-05），矩阵为 PostgreSQL 14 与现代版本 17；不将 17 通过当作 14 已证明，两档都必须实测。精确镜像版本与摘要应在引入 service 时核实并冻结，历史镜像不可获取则记录受阻，不静默换版本。SQLite 在报告中输出实际 engine 版本。ClickHouse 只作独立日志库、TimescaleDB 只作 PostgreSQL 日志扩展，在对应后续阶段单独建矩阵，不作为第四/第五种主库。

不自动连接或修改现有数据库。历史升级 fixture 从已审阅的源码/schema构造，不上传生产备份；需要真实脱敏样本时单独取得授权。P8 才进行完整升级与回滚演练；P0 冻结集合与方案，P1 验证连接及公共配置行为。

## 外部服务及副作用

P2 起所需 Redis 在每 job 内临时启动。邮件、支付、OAuth、机器人和上游 AI 使用 job 内模拟器，仅监听 loopback 随机可用端口，由父测试持有句柄并在结束或取消时关闭。每个请求目标显式注入，测试不得读取真实 API key；未配置模拟地址直接失败，不回落默认生产地址。

模拟测试应断言未调用的出口；应用客户端的测试配置只允许明确模拟地址，关闭默认自动重定向。不能把这一应用级限制描述成 runner 全网络隔离：依赖下载需联网，测试阶段的真实出口限制须由对应实现和测试验证。签名 fixture 使用明确公开测试密钥，不包含生产秘密。影子实例禁止发送通知、执行真实支付或重复消费有副作用的任务。

## 契约与证据

fixture 标明来源 commit、原始文件/行号、源码推导或运行采集、适用阶段及脱敏方法。源码推导不得标记为 Go 运行结果。公共配置比较字符串及 JSON 字段，不比较对象 key 顺序；金额/额度使用原整数单位和精确断言。

每次验收记录新仓库 SHA、上游 SHA、run ID、attempt、runner/数据库/工具链版本、精确命令、退出码、测试与跳过数量。跳过不是通过。原始 artifact 默认保留七天，长期保留经过审查的摘要和必要脱敏 fixture；禁止上传环境变量全集、凭证、真实请求正文、数据库文件或完整生产日志。

P0 已存在 Go 基线与工具查询证据见 ci-baseline.md。本文是隔离方案，不宣称任何尚未创建的数据库/模拟器矩阵已执行。每阶段独立 verification 核查精确 SHA 的证据；FAIL 修复重验，PARTIAL 不冒充该阶段完成。
